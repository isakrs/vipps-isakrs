Data Insights

Data products make analytics work ownable.

One configuration file declares the product boundary. The platform creates the resources. The team ships and operates the data product.

Configurationdescribes ownership, deployment, access, and publishing
Platformcreates durable Azure and Databricks resources
Teambuilds trusted outputs on top of a stable contract
Configuration contractName, owner, repository, source views, environment, notifications.
->
Provisioned boundaryStorage, Unity Catalog schema, identities, credentials, access group.
Databricks bundleJobs run as the product runner identity, not as a person.
->
Product outputsTables, views, reports, or external publications with a clear owner.
Why now

The useful data is often less formal than the work depending on it.

Today Important outputs live in shared places.

Many recurring tables start in `analytics_workbench.public` or a team-owned schema because that is fast and practical.

Risk The operating model is hidden.

Run identity, secrets, write permissions, table ownership, and downstream access can be spread across people, notebooks, and manual setup.

Direction Make the boundary explicit.

A data product collects the technical and governance shape into one reviewed configuration and one durable resource set.

Configuration

Small configuration file, large operational effect.

consumers/data-products/hibob-data-insights.yamlshape
config_schema: data-product-configuration-v1

name: hibob-data-insights
short_name: hibobdi
owner: <responsible-person>@vippsmobilepay.com
environment: prod

description: |
  Public employee hierarchy and cost centre
  history for Data Insights reporting.

key_vault: true

github_repos:
  - repo: vippsas/vmp-data-product-hub
    environments:
      - hibob-data-insights-prod

data_access:
  - name: current_employees
    query: SELECT ...

notifications:
  - channel: "#data-insights-alerts"
1
Identity and ownership`name`, `short_name`, `owner`, and `environment` decide the durable names and accountability.
2
Deployment trust`github_repos` maps a repository and GitHub Environment to the deployer identity using OpenID Connect.
3
Data boundary`data_access` creates source views the runner can read, while output tables stay in the product schema.
4
Operations`key_vault` and `notifications` make secrets and alerting product-owned instead of personally owned.
Resources created

The platform turns the contract into the same resource layout every time.

Storage account

`stdp<short_name><environment>` for managed tables, input files, and job artifacts.

Unity Catalog schema

`data_products.<name>` becomes the owned place for product views and output tables.

Source views

Every `data_access` entry becomes a view the runner can use for transformations.

Runner identity

`appl-dp-<name>-runner-<environment>` runs production jobs and writes product tables.

Deployer identity

`appl-dp-<name>-deployer-<environment>` deploys bundles from GitHub Actions.

Federated credential

Repository and environment are linked through OpenID Connect, so no long-lived deploy secret is needed.

Key Vault

`akv-dp-<short_name>-<environment>` stores product-owned secrets and notification webhooks.

Entra ID group

`data-product-<name>-<environment>` controls who can query and operate the product.

Flow

Configuration owns the boundary. Product hub owns the logic.

This separation lets Data Insights change notebooks, dashboards, and reports without rediscovering infrastructure rules each time.

1
Data product configurationReviewed in `vmp-data-platform-config` with the rest of the platform configuration.
2
Terraform variablesThe platform generator serializes the configuration into `data_products.auto.tfvars.json`.
3
Platform applyAzure and Databricks resources are created with consistent names and permissions.
4
Databricks bundle`vmp-data-product-hub` deploys jobs that run as the product runner identity.
5
Trusted outputTables, reports, dashboards, or external shares are tied to one durable owner.
Concrete example

HiBob Data Insights is a good candidate.

Current shape

Useful tables, but personal operation

The existing bundle imports HiBob employee hierarchy and cost centre history on weekdays at 05:00 Europe/Oslo.

  • Reads HiBob credentials from an existing finance-owned secret scope.
  • Runs as a personal user account.
  • Writes `hibob_current_employees`, `hibob_employees_history`, and `hibob_cost_centre_history` to `analytics_workbench.public`.
  • Deliberately does not fetch or publish salary data.
Data product shape

Same business value, stronger ownership

The job can move behind a product boundary that Data Insights can operate as a team.

  • Writes to `data_products.hibob_data_insights`.
  • Runs as `appl-dp-hibob-data-insights-runner-prod`.
  • Deploys from `vmp-data-product-hub` through a protected GitHub Environment.
  • Stores secrets and alerts with the product, not a person.
Value

Why this is valuable for Data Insights.

1
Continuity

Production jobs run as a stable product identity, so a useful report does not depend on one person's account.

2
Safer access

The team owns a clear schema and access group. Consumers still use analytics projects when they need governed read access.

3
Faster reviews

Reviewers see the owner, environment, source access, deploy repository, and publishing surface in one file.

4
Reusable pattern

Once the first product is in place, the next recurring report starts from a known layout instead of a fresh platform discussion.

Next move

Make the first product boring, then copy the pattern.

Step 1Declare the product

Add `consumers/data-products/hibob-data-insights.yaml` with ownership, repository trust, Key Vault, notifications, and source views.

Step 2Move the bundle

Update the Databricks Asset Bundle to run as the runner identity and write to `data_products.hibob_data_insights`.

Step 3Validate in production shape

Deploy through GitHub Actions, trigger the job, verify the three output tables, and make the run visible to the team.

The outcome: a data product that is easier to operate, easier to review, and easier for others to trust.
